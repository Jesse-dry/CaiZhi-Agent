## 1. 背景：为什么要做数据

我们现在不是"为了不用大模型才写 data"，而是**为了让大模型变成我们自己的材料教学 Agent**。

| 数据文件 | 作用 | 没有它，Agent 会怎样 |
|---|---|---|
| `terms.csv` | 术语标准（中英对照 + 定义） | 术语翻译不一致，解释不专业 |
| `knowledge_graph.json` | 材料因果链（因果推理依据） | 只会泛泛而谈，无法逐步推导因果 |
| `questions.json` | 错题误区库（诊断依据） | 无法精准定位学生错在哪里 |
| `socratic.json` | 引导路径（追问依据） | 无法一步步引导学生自己推导 |
| `feynman.json` | 评分标准（评价依据） | 无法判断学生是否真正理解了 |
| `qa_cases.json` | 测试集（质量验证） | 不知道 Agent 回答得好不好 |

**一句话总结：** 后面接入大模型后，Agent 会读取这些 data，再生成个性化答疑、诊断、追问和评价。没有这些 data，大模型就是普通聊天；有了这些 data，它才是"材料学习智能体"。

**V1 知识范围：** Fe-C 相图与钢的热处理（淬火、回火、退火、正火、马氏体转变等）。

每条链请按以下格式写（以 C003 为例）：

---

**【chain_id】** C003

**【中文标题】** 淬火后为什么要回火

**【英文标题】** Why is tempering usually performed after quenching?

**【中文标准问题】** 为什么淬火后通常还要回火？

**【英文标准问题】** Why is tempering usually performed after quenching?

**【因果路径】**（用箭头连接，每个节点一行）

```
淬火
→ 快速冷却
→ 形成马氏体
→ 硬度提高
→ 脆性增大
→ 内应力增大
→ 回火
→ 释放内应力
→ 降低脆性
→ 提高韧性
```

**【一句话总结】** 淬火形成硬而脆的马氏体并产生内应力；回火可以释放内应力、降低脆性、改善韧性，从而在硬度和韧性之间获得更好的平衡。

**【标准答案】**（3-5 句话，供 Agent 参考）
淬火后钢中常形成硬而脆的马氏体，并伴随较大的内应力。如果直接使用，材料容易发生脆性断裂。回火是在淬火后重新加热到较低温度，使组织和内应力得到调整，从而降低脆性、改善韧性，并在硬度和韧性之间取得更好的平衡。

**【关键点 checklist】**（学生回答中必须覆盖的点）

1. 淬火后形成马氏体
2. 马氏体硬度高但脆性大
3. 淬火后可能存在内应力
4. 回火可以释放/降低内应力
5. 回火可以降低脆性、提高韧性
6. 回火是为了改善综合力学性能（硬度和韧性的平衡）

**【涉及术语】**（从术语表中挑，写中英对照）

- 淬火 / Quenching
- 回火 / Tempering
- 马氏体 / Martensite
- 硬度 / Hardness
- 脆性 / Brittleness
- 韧性 / Toughness

**【常见误区】**

1. 以为回火是为了继续大幅提高硬度
2. 以为淬火后钢已经性能最好，不需要后续处理
3. 以为回火会让钢完全失去硬度
4. 混淆退火和回火

**【中文检索关键词】**（竖线分隔）

### 5.4 另附：完整体量示例（C002 马氏体为什么硬而脆）

---

**【chain_id】** C002

**【中文标题】** 马氏体为什么硬而脆

**【英文标题】** Why is martensite hard but brittle?

**【中文标准问题】** 为什么马氏体硬度高但脆性也大？

**【英文标准问题】** Why does martensite have high hardness but also high brittleness?

**【因果路径】**

```
快速冷却（淬火）
→ 碳原子扩散受限
→ 奥氏体 → 马氏体（无扩散相变）
→ 碳原子过饱和固溶于 α-Fe
→ 晶格严重畸变
→ 位错运动受阻
→ 硬度提高
→ 塑性变形能力丧失
→ 脆性增大
```

**【一句话总结】** 马氏体中的过饱和碳原子造成严重晶格畸变，阻碍位错运动，使硬度提高的同时塑性变形能力丧失，因此硬而脆。

**【标准答案】**
马氏体是碳在 α-Fe 中的过饱和固溶体。由于淬火冷却速度极快，碳原子来不及以渗碳体形式析出，被"困"在体心立方晶格中，造成严重的晶格畸变。晶格畸变会强烈阻碍位错运动——位错运动是金属塑性变形的主要机制，位错越难运动，材料就越硬、越不容易发生塑性变形。但正是因为塑性变形能力被压制，材料在断裂前几乎没有塑性变形，表现出脆性。

**【关键点 checklist】**

1. 马氏体是碳的过饱和固溶体
2. 过饱和碳造成晶格畸变
3. 晶格畸变阻碍位错运动
4. 位错受阻 → 硬度提高
5. 塑性变形被压制 → 脆性大

**【涉及术语】**

- 马氏体 / Martensite
- 淬火 / Quenching
- 碳原子扩散 / Carbon diffusion
- 无扩散相变 / Diffusionless transformation
- 晶格畸变 / Lattice distortion
- 位错运动 / Dislocation motion
- 硬度 / Hardness
- 脆性 / Brittleness

**【常见误区】**

1. 以为马氏体硬是因为晶粒特别细
2. 以为马氏体脆是因为含碳量太低
3. 以为硬度高就一定韧性好

**【中文检索关键词】**
马氏体 | 晶格畸变 | 位错运动 | 硬度 | 脆性 | 过饱和 | 无扩散相变

**【英文检索关键词】**
martensite | lattice distortion | dislocation motion | hardness | brittleness | supersaturated | diffusionless transformation

**【可能所在章节】**
- 中文教材：钢的热处理；马氏体转变
- 英文教材：Martensitic transformation; Heat treatment of steels

**【推荐下一步学习】**
回火 | 马氏体组织 | 回火马氏体 | 贝氏体

## 7. 任务四：编写苏格拉底引导链 socratic.json

### 7.1 是什么

苏格拉底引导链 = 一组由浅入深的追问，引导学生自己推导出结论，而不是直接告诉答案。

### 7.2 填写模板

```json
{
  "socratic_id": "S___（按顺序编号，S002 开始）",
  "chain_id": "C___（关联的因果链编号）",
  "title": "引导学生理解XXX",
  "steps": [
    {
      "step": 1,
      "question": "（第一步追问，从最直观的问题入手）",
      "expected_keywords": ["关键词1", "关键词2"],
      "hint": "（学生答不出时的提示）",
      "explanation_if_wrong": "（学生答错时的纠正解释）"
    },
    {
      "step": 2,
      ...
    }
  ],
  "final_summary": "（所有步骤走完后，给学生的一句话总结）"
}
```

### 7.3 编写要点

- **6 步左右**为一组，从现象到本质，逐步深入
- 每个 step 的 `expected_keywords` 是用来匹配学生回答的，要写**学生可能说的关键词变体**
- `hint` 是提示，不是直接答案——引导学生自己想到
- `explanation_if_wrong` 是兜底：学生实在答不出或答错了，给正确答案

### 7.4 示例：参照现有 S001

S001（引导学生理解淬火为什么提高硬度）有 6 个步骤：
1. 淬火和退火最大的工艺差别 → 2. 冷却速度对碳原子扩散的影响 → 3. 扩散受限后形成什么组织 → 4. 马氏体中碳原子造成什么变化 → 5. 晶格畸变如何影响位错运动 → 6. 位错受阻后宏观性能如何变化

每一步都从学生的上一个答案自然引出下一个问题。

## 8. 任务五：编写费曼评价标准 feynman.json

### 8.1 是什么

费曼学习法：让学生用自己的话解释一个概念，然后用 checklist 评价他是否真正理解了。

### 8.2 填写模板

```json
{
  "feynman_id": "F___（按顺序编号，F002 开始）",
  "topic": "（评价主题，一句话）",
  "chain_id": "C___（关联的因果链编号）",
  "prompt": "（给学生的费曼任务描述，比如'请你用自己的话向同学解释：XXX'）",
  "checklist": [
    {
      "point": "（评价维度，比如'指出淬火的核心是快速冷却'）",
      "keywords": ["关键词1", "关键词2"]
    }
  ],
  "rubric": {
    "concept_accuracy": （概念准确性权重，整数，总分100）,
    "causal_chain_completeness": （因果链完整度权重）,
    "terminology": （术语使用权重）,
    "application_transfer": （应用迁移能力权重）,
    "clarity": （表达清晰度权重）
  },
  "excellent_example": "（一段优秀回答的范例文本）"
}
```

### 8.3 编写要点

- checklist 通常 **5-7 个点**，每个点配 2-3 个关键词
- rubric（评分权重）总分 100，`causal_chain_completeness`（因果链完整度）通常权重最高
- `excellent_example` 是一段标准满分回答，给 Agent 做参考

## 9. 任务六：编写测试用例 qa_cases.json

### 9.1 是什么

测试集 = 真实学生可能问的问题 + Agent 应该给出的参考答案。用来验证我们的 Agent 好不好用。

### 9.2 填写模板

```json
{
  "case_id": "QA___（按顺序编号）",
  "question": "（学生的问题，尽量用口语化的表达）",
  "answer": "（参考答案，3-5句即可）",
  "topic": "（所属主题）",
  "related_chains": ["C___"],
  "difficulty": "basic / intermediate / advanced",
  "type": "factual / causal / comparative / application"
}
```

### 9.3 问题类型说明

| 类型 | 说明 | 示例 |
|---|---|---|
| `factual` | 事实性问题 | "什么是马氏体？" |
| `causal` | 因果推理 | "为什么淬火后钢变硬了？" |
| `comparative` | 对比分析 | "退火和回火有什么区别？" |
| `application` | 应用场景 | "一把刀太脆了容易断，可能是热处理哪个环节出了问题？" |

### 9.4 写什么

不需要很正式的答案，给出**你认为 Agent 应该覆盖到的要点**即可。尽量覆盖不同类型的真实学生问题。

目标是 **10–20 条**。

## 10. 知识图谱节点命名规范

当你写因果链时，会涉及到各种节点。为了避免日后混乱，所有技术同学在录入图谱时会遵循以下命名规范。你不需要自己起节点 ID，但**了解这个规范有助于你写因果链时用词一致**：

```
# 工艺类节点
process_quenching        # 淬火
process_tempering        # 回火
process_annealing        # 退火
process_normalizing      # 正火

# 组织/相类节点
phase_austenite          # 奥氏体
phase_martensite         # 马氏体
phase_pearlite           # 珠光体
phase_ferrite            # 铁素体
phase_cementite          # 渗碳体
phase_bainite            # 贝氏体

# 机制类节点
mechanism_diffusion_suppressed    # 扩散受限
mechanism_dislocation_blocked     # 位错运动受阻
mechanism_lattice_distortion      # 晶格畸变
mechanism_solid_solution          # 固溶强化
mechanism_grain_refinement        # 细晶强化

# 性能类节点
property_high_hardness            # 高硬度
property_high_toughness           # 高韧性
property_brittleness              # 脆性
property_high_strength            # 高强度
property_high_ductility           # 高塑性
property_internal_stress          # 内应力
```

**核心原则：一个节点只建一次，后面所有链都复用。** 比如 `phase_martensite` 已经存在，所有涉及马氏体的链都继续使用它，不要新建 `martensite_1`、`phase_martensite_new` 之类的重复节点。

## 11. ⚠️ 最重要的规则

### 11.1 字段名绝对不能改！

程序代码是按字段名来读取数据的。举个例子：

| ✅ 程序读取的字段名 | ❌ 不能改成 |
|---|---|
| `question_id` | `questionId` |
| `next_socratic_id` | `socratic_id_next` |
| `expected_keywords` | `keywords` |
| `chain_id` | `chainId` |

**改了字段名，前端和后端都会报错，Agent 就废了。**

### 11.2 列名绝对不能改！

`terms.csv` 的 12 列是固定的。不要新增列、不要删除列、不要改列名。如果某个字段没有内容，就留空（两个逗号 `,,` 之间什么都不写）。

### 11.3 ID 编号规则

| 前缀 | 含义 | 格式 | 当前到哪了 |
|---|---|---|---|
| `T` | 术语 | T + 三位数字 | T010 |
| `C` | 因果链 | C + 三位数字 | C001 |
| `Q` | 错题 | Q + 三位数字 | Q001 |
| `S` | 苏格拉底链 | S + 三位数字 | S001 |
| `F` | 费曼评价 | F + 三位数字 | F001 |
| `QA` | 测试用例 | QA + 三位数字 | 从 QA001 开始 |

### 11.4 推荐工作流：你写模板 → AI 转 JSON → 我来审核

**最省力的方式是这样的：**

```
① 你照着上面的模板，把内容填好（纯文本即可，不用管 JSON 格式）
    ↓
② 把填好的模板丢给 Claude Code，说：
   "帮我把这个内容包转成 questions.json / socratic.json / feynman.json 的格式，参照现有文件的字段结构"
    ↓
③ AI 帮你生成 JSON → 你复制粘贴到对应的 data/ 文件里
    ↓
④ git push 推送到仓库，或者直接微信发我文件
```

**为什么推荐这样？**
- 你不用纠结 JSON 的逗号、引号、括号这些细节——AI 帮你处理
- JSON 格式有问题 AI 也能帮你排查（参考 `docs/新手上手指南.md` 第 7 节）
- 节省你大量时间，把精力放在内容质量上

**如果你不想自己动手转 JSON：** 直接把填好的模板草稿发我（Word / 记事本 / 微信消息都行），我来转。两种方式都 OK。

**如果你想自己直接编辑 JSON 文件：** 也可以，但注意逗号、引号、括号这些细节，改完在命令行跑一下验证：

```bash
node -e "JSON.parse(require('fs').readFileSync('data/questions.json','utf8')); console.log('✅ JSON 合法')"
```
