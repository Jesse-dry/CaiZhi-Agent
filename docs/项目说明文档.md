## 一、项目概述

### 1.1 项目定位

**材智 Agent (CaiZhi)** 是一款面向材料科学与工程专业学生的 AI 智能学习助手。系统以**大语言模型 + 检索增强生成（RAG）+ 知识图谱**为核心技术，围绕"铁碳相图与钢的热处理"知识单元，构建了一个从**智能答疑 → 错题诊断 → 苏格拉底引导 → 费曼评价 → 学习路径推荐**的完整学习闭环。

### 1.2 核心理念

传统 AI 答疑工具往往直接给出答案，学生"知其然不知其所以然"。材智 Agent 的核心理念是引导学生从"获取答案"走向"理解因果链、清晰表达知识、实现应用迁移"。

**三阶段学习哲学：**

1. **Know（知道）** — 通过 RAG 检索教材原文，提供准确、有据可查的知识回答
2. **Understand（理解）** — 通过因果链溯源和苏格拉底式追问，打通"工艺→组织→性能"的深层逻辑
3. **Transfer（迁移）** — 通过费曼学习法和个性化路径推荐，将知识内化为可迁移的能力

### 1.3 V1 范围

当前版本为 **V1 最小可行性测试版**，聚焦于单一知识单元：

> **铁碳相图与钢的热处理**（Fe-C Phase Diagram & Heat Treatment of Steel）

涵盖的知识点包括：淬火、回火、退火、正火、奥氏体、马氏体、珠光体、晶格畸变、位错运动、TTT 曲线、CCT 曲线、亚共析钢/过共析钢等。

## 二、六大核心能力

| 序号 | 能力模块 | 页面 | 说明 |
|------|----------|------|------|
| 1 | **智能答疑** (Smart Answering) | `1_Smart_Answering` | RAG 增强的教材问答，结合知识图谱因果链、术语表和自测题，提供结构化回答 |
| 2 | **错题诊断** (Error Diagnosis) | `2_Error_Diagnosis` | 对学生的错误选项进行误区溯源，定位知识盲区，推荐补救路径 |
| 3 | **苏格拉底引导** (Socratic Guidance) | `3_Socratic_Guidance` | 通过递进式提问启发学生自己推导出正确答案，而非直接告知 |
| 4 | **费曼评价** (Feynman Evaluation) | `4_Feynman_Evaluation` | 让学生用自己的话解释概念，AI 从 5 个维度评估因果链的完整性和准确性 |
| 5 | **知识图谱** (Knowledge Graph) | `5_Knowledge_Graph` | 可视化材料学科知识点关联网络，展示"工艺→组织→性能"因果链 |
| 6 | **学习路径推荐** (Learning Path) | `6_Learning_Path_Recommendation` | 聚合各阶段薄弱点，基于先修关系拓扑排序，生成个性化学习路径 |

## 三、学习闭环设计

### 3.1 五阶段流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ 1.智能答疑 │ ──→ │ 2.错题诊断 │ ──→ │ 3.苏格拉底│ ──→ │ 4.费曼评价│ ──→ │ 5.学习路径│
│    QA     │     │ Diagnosis │     │ Socratic  │     │ Feynman   │     │   Path    │
└──────────┘     └──────────┘     └─────┬────┘     └─────┬────┘     └──────────┘
                                         │                │
                                         │    ┌───────────┘
                                         │    │ (费曼不通过则回到苏格拉底)
                                         ▼    ▼
                                     ┌──────────┐
                                     │ 3.苏格拉底│ ← 循环强化
                                     └──────────┘
```

### 3.2 状态机守卫条件

学习闭环由 `workflows/learning_loop.py` 中的状态机驱动，后端强制执行合法的阶段转换：

| 当前阶段 | 目标阶段 | 守卫条件 |
|----------|----------|----------|
| QA | DIAGNOSIS | 无条件 |
| DIAGNOSIS | FEYNMAN | 诊断通过（学生答对） |
| DIAGNOSIS | SOCRATIC | 诊断未通过（学生答错） |
| SOCRATIC | FEYNMAN | 无条件 |
| FEYNMAN | RECOMMENDATION | 费曼评分 ≥ 60/78 |
| FEYNMAN | SOCRATIC | 费曼评分 < 60/78（回头加强） |
| RECOMMENDATION | COMPLETED | 无条件 |
| 任意阶段 | QA | 无条件（可随时重启） |

即使前端请求乱序到达，状态机也会拒绝非法转换，返回 409 Conflict。

### 3.3 数据流与会话状态

所有跨阶段上下文通过 `LearningSession`（Pydantic 模型）统一管理：

```python
# 会话状态结构
LearningSession:
  session_id, user_id              # 身份标识
  current_stage                     # 当前阶段
  current_knowledge_id, chain_id    # 知识单元 & 因果链 指针
  current_question_id               # 当前自测题
  current_socratic_id               # 苏格拉底链
  current_feynman_id                # 费曼评价标准
  qa_result, diagnosis_result       # 各阶段结果 (dict)
  socratic_result, feynman_result
  recommendation_result
```

## 四、技术架构

### 4.1 四层架构

项目采用**四层清洁架构**，严格控制依赖方向，为从 Streamlit 迁移到 FastAPI + React/Vue 做好准备：

```
┌──────────────────────────────────────────────────────────────┐
│  表示层 PRESENTATION                                          │
│  pages/ (Streamlit)  │  api/ (FastAPI, 部分就绪)              │
│  UI 渲染，无业务逻辑                                           │
├──────────────────────────────────────────────────────────────┤
│  服务层 SERVICES & WORKFLOWS                                  │
│  services/ (6 个服务)  │  workflows/ (状态机)                  │
│  用例编排，与传输层无关（不导入 Streamlit 或 FastAPI）           │
├──────────────────────────────────────────────────────────────┤
│  领域层 DOMAIN                                                │
│  schemas/ (Pydantic v2, 16 个文件)  │  repositories/ (3 个 ABC)│
│  统一数据协议 + 抽象接口                                       │
├──────────────────────────────────────────────────────────────┤
│  基础设施层 INFRASTRUCTURE                                     │
│  infrastructure/ (ChromaDB, LLM Client, Session 存储)          │
│  rag/ (PDF→Markdown→Chunk→Vector Store→Retrieval)             │
│  knowledge/ (图谱, 术语, 误区, 提示构建)                        │
├──────────────────────────────────────────────────────────────┤
│  数据层 DATA                                                  │
│  data/ (JSON/CSV)  │  C:/chroma_data/ (ChromaDB 向量库)       │
└──────────────────────────────────────────────────────────────┘
```

**关键架构原则：**

- `services/`、`workflows/`、`rag/`、`agents/` **绝不导入** `streamlit`
- 所有跨层数据使用 Pydantic `schemas/` 模型，不使用裸字典
- `repositories/` 定义抽象接口（ABC），`infrastructure/` 提供具体实现
- 服务类采用**构造器依赖注入**，便于测试和替换

### 4.2 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| **当前前端** | Streamlit | V1 生产前端（`pages/` 目录） |
| **未来前端** | React 18+ / Vue 3 + Vite + TypeScript | 架构已规划（`frontend/README.md`） |
| **未来后端** | FastAPI + Uvicorn | API 框架已就绪（`api/main.py`） |
| **LLM** | Anthropic Claude / DeepSeek / OpenAI | 通过 `infrastructure/llm_client.py` 统一封装 |
| **RAG 检索** | ChromaDB + BGE-M3 / DashScope text-embedding-v4 | 双语向量库（zh/en/images 三个 Collection） |
| **Embedding** | DashScope API（优先）+ BGE-M3 本地（fallback） | 1024 维，零本地内存模式 |
| **知识图谱** | NetworkX + JSON | 8 节点 7 边的有向因果图 |
| **PDF 解析** | Marker（视觉 AI 解析器） | 支持双栏排版、公式→LaTeX、表格→Markdown |
| **图片理解** | Qwen-VL-Max（DashScope） | 935 张教材图片的结构化标注 |
| **数据校验** | Pydantic v2 | 全项目统一数据协议 |
| **流式通信** | SSE (Server-Sent Events) | 10 种细粒度流式事件类型 |
| **向量库** | ChromaDB 1.5.9 | 持久化存储到 `C:\chroma_data\` |

### 4.3 API 设计

RESTful API 围绕**资源 + 操作**设计（非页面名），完整端点清单：

```
POST   /api/v1/sessions/                         创建学习会话
GET    /api/v1/sessions/{id}                     获取会话状态
DELETE /api/v1/sessions/{id}                     删除会话
POST   /api/v1/sessions/{id}/qa-runs             创建答疑任务 → 201 + {run_id, events_url}
POST   /api/v1/sessions/{id}/diagnoses           提交错题诊断
POST   /api/v1/sessions/{id}/socratic/answers    提交苏格拉底回答
POST   /api/v1/sessions/{id}/feynman-evaluations 提交费曼评价
GET    /api/v1/sessions/{id}/recommendations     获取学习路径
GET    /api/v1/sessions/{id}/knowledge-graph     获取知识图谱
GET    /api/v1/runs/{id}                         获取 run 结果
GET    /api/v1/runs/{id}/events                  SSE 事件流 (Last-Event-ID 断线重连)
DELETE /api/v1/runs/{id}                         删除 run
GET    /api/health                               健康检查
```

**SSE 流式事件协议** (`schemas/events.py`)：定义了 10 种细粒度事件类型 — `run.started`、`retrieval.started`、`retrieval.source_found`、`retrieval.completed`、`generation.started`、`generation.delta`、`generation.section_completed`、`workflow.stage_changed`、`run.completed`、`run.failed`。

## 五、RAG 管线

### 5.1 管线全貌

```
PDF 教材 ──→ Marker 解析 ──→ Markdown ──→ 语义分块 ──→ Embedding ──→ ChromaDB
                │                               │              │
                └──→ 图片提取 ──→ Qwen-VL-Max ──→ 图片标注 ────┘
```

### 5.2 执行结果

| 步骤 | 状态 | 详情 |
|------|------|------|
| PDF → Markdown | ✅ 已完成 (5090 服务器) | 中文教材 1.74MB/70 页，英文教材 3.13MB/~900 页 |
| 图片标注 | ✅ 已完成 (Qwen-VL-Max) | 935 张图片结构化描述，~¥5-8 |
| 语义分块 | ✅ 已完成 | 中文 1,523 chunks + 英文 3,234 chunks + 图片 935 chunks |
| 向量库构建 | ✅ 已完成 | 3 个 ChromaDB Collection，共 5,692 chunks，~70MB |
| 双语检索 | ✅ 可用 | DashScope API 优先，BGE-M3 本地 fallback |

### 5.3 数据源约束

智能答疑严格基于四类数据源，各有权责边界：

| 数据源 | 角色 | 禁止 |
|--------|------|------|
| 教材 RAG | 事实依据：定义、原理、组织转变、性能变化 | — |
| 知识图谱 | 因果链路径 | 编造新节点 |
| 术语表 (`terms.csv`) | 标准化术语翻译 | LLM 自行发明翻译 |
| 题库 (`questions.json`) | 自测题匹配 | LLM 临时出题 |

## 八、快速开始

### 8.1 环境准备

```bash
# 克隆项目
git clone <repo-url>
cd CaiZhi-Agent

# 创建虚拟环境
python -m venv venv
source venv/Scripts/activate  # Windows Git Bash
# 或 venv\Scripts\activate   # Windows CMD

# 安装依赖
pip install -r requirements.txt
```

### 8.2 配置 API Key

在项目根目录创建 `.env` 文件：

```env
DASHSCOPE_API_KEY=your_dashscope_api_key    # 阿里云 DashScope（Embedding 必需）
ANTHROPIC_API_KEY=your_anthropic_api_key    # Anthropic Claude（LLM，V2 需要）
DEEPSEEK_API_KEY=your_deepseek_api_key      # DeepSeek（可选）
```

### 8.3 启动应用

```bash
# Streamlit 前端（当前方式）
streamlit run app.py

# FastAPI 后端（未来方式）
uvicorn api.main:app --reload --port 8000
```

### 8.4 RAG 管线命令

```bash
# 检查分块质量
python -m rag.check_chunks

# 构建向量库（DashScope API，推荐）
python -m rag.build_vector_store --backend dashscope

# 构建向量库（本地 BGE-M3）
python -m rag.build_vector_store --backend local

# 验证检索
python -c "from rag.bilingual_retriever import BilingualRetriever; r = BilingualRetriever(); print(r.retrieve('淬火'))"
```

## 十、关键设计决策

### 10.1 为什么用关键词规则引擎（V1）而非直接接 LLM？

V1 阶段，苏格拉底判定、费曼评分、推荐映射三个服务使用**关键词匹配规则引擎**。这是有意的设计选择：

- **接口先行**：先定义清晰的输入输出 schema（Pydantic 模型），确保接口稳定
- **可降级运行**：在网络不可用或 API 配额耗尽时，系统仍可提供基础功能
- **零成本调试**：规则引擎的输出完全可预测，便于端到端流程验证
- **LLM 即插即用**：每个规则函数都有明确的"LLM 替换点"，只需替换内部实现，接口不变

### 10.2 为什么用构造器依赖注入而非全局单例？

`QAService` 等服务类通过 `__init__` 接受依赖（RAG 仓库、知识仓库、LLM 客户端），而非在内部 `import`：

- **可测试性**：可以注入 mock 实现做单元测试
- **传输层无关**：同一份服务代码在 Streamlit 和 FastAPI 下都能工作
- **灵活替换**：切换向量库后端（ChromaDB → Pinecone）或 LLM 提供商只需改注入，不碰业务逻辑

### 10.3 为什么学习闭环需要状态机？

学生在学习闭环中可能跳页、回退、刷新。如果没有后端状态机：

- 前端发来"在 QA 阶段就请求费曼评价"的请求 → 应该拒绝
- 费曼不通过 → 应该强制回到苏格拉底，而非跳到推荐

`workflows/learning_loop.py` 的状态机确保**后端是阶段转换的唯一权威**，前端只是请求者。

### 10.4 ChromaDB Windows 兼容性

ChromaDB 在 Windows 上有两个已知问题，已在项目中规避：

1. **中文路径 bug**：向量库存储在 `C:\chroma_data\`（纯 ASCII），通过 `CHROMA_DATA_DIR` 环境变量可自定义
2. **多客户端锁冲突**：惰性单例模式，每次只打开一个 PersistentClient，用完立即释放
